# Price Hunter

Личный мониторинг цен для Астаны: React + TypeScript + Vite, Python-сборщик, JSON, история наблюдений и Telegram Bot API. Покупки и оплата выполняются человеком. Порог находок — реальная скидка **от 90%**.

Первый запуск на серверах GitHub при выключенном компьютере: **[пошаговая инструкция](GITHUB_START.md)**. Перед включением расписания ознакомьтесь с ограничениями Actions ниже.

Это работающий MVP с **одним подтверждённым сборщиком — Technodom**. Остальные восемь магазинов имеют отдельные классы адаптеров, диагностику и честные статусы, но не готовые парсеры. Не обещается охват всех каталогов или наличие аномалий. Неподтверждённые цены, расходы и варианты не подставляются.

## Что уже работает

- Обнаружение новых товаров через четыре реальные страницы категорий Technodom в Астане: наушники, ноутбуки, SSD, стиральные машины. Это первые страницы, без неисследованной пагинации. Ссылки обнаруживаются из HTML; API и CSS-селекторы не придуманы.
- Повторные проверки, отдельные наблюдаемые ссылки, ограничение числа запросов и чередование товаров/категорий.
- JSON-LD Product/Offer и проверка публичного `__NEXT_DATA__`: SKU, полная цена, старая цена, контекст города, остатки в точках самовывоза. При расхождении цен карточка отвергается. Внутренний `mpn`, равный SKU магазина, не считается моделью производителя.
- История, независимые расчёты исторического снижения и рыночного отклонения, фильтры, избранное браузера, карточка товара, график и источники сравнения, состояние источников, устаревшие данные.
- Telegram с отдельным тестом, долговечным журналом, защитой от повторов и обработкой 429. Обычный запуск не отправляет тестовое сообщение.
- Данные в отдельной ветке `price-data`, атомарная запись локальных JSON, блокировка локального процесса и concurrency для Actions.

**Ограничение доказательств:** сейчас у живого источника не опубликованы все поля упаковки/состояния и окончательные расходы. Поэтому наблюдаемые обычные товары остаются в «Наблюдении», а не становятся подтверждёнными находками. Рыночное сравнение реализовано и проверено тестами, но трёх независимых живых магазинов в этой версии нет. Автоматически накапливается история для выявления возможного снижения; полная проверка условий нужна для подтверждения. Одно наблюдение или зачёркнутая цена скидку не доказывают.

## Размещение и условия бесплатного использования

Условия проверены 11 октября 2026 по официальной документации.

**GitHub Pages не выбран для выдачи предложений.** Его правила ограничивают сайты, основной целью которых является содействие коммерческим сделкам. Каталог скидок с переходами к покупке может подпадать под это условие; это консервативная оценка назначения Price Hunter, а не решение GitHub о конкретном проекте. Для такой выдачи используется **Cloudflare Pages Free**; GitHub хранит исходники и очищенные данные. [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

У GitHub Actions есть отдельные ограничения назначения hosted runners и использования Actions как приложения/serverless-сервиса. По запросу пользователя `Collect prices` теперь использует **облачный `ubuntu-latest`** по умолчанию; расписание выключено до установки `PRICE_HUNTER_ENABLED=true`. Это экспериментальный способ запуска: GitHub не подтверждал совместимость постоянного мониторинга с условиями, а бесплатные минуты не являются разрешением на произвольный мониторинг. Для собственного исполнителя можно установить `PRICE_HUNTER_RUNNER_LABELS=["self-hosted", "price-hunter"]` или использовать локальный цикл. [Условия Actions](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features#actions), [self-hosted runners](https://docs.github.com/en/actions/concepts/runners/self-hosted-runners).

Стандартные hosted runners для публичных репозиториев бесплатны; для private действуют квоты плана. Self-hosted требует вашего оборудования и его питания. Ни бесплатный VPS, ни круглосуточная работа выключенного компьютера не обещаются. [Биллинг Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

Cloudflare Pages Free имеет лимит 500 сборок в месяц, 20 000 файлов, 25 MiB на файл. Интерфейс публикуется только при изменении исходников; новые цены браузер получает из публичной ветки данных, без нового деплоя каждые 15 минут. Используются только статические файлы, без платных API и Workers Functions. [Лимиты](https://developers.cloudflare.com/pages/platform/limits/), [Direct Upload из CI](https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/).

## 1. Локальный запуск

Нужны Git, Node.js 20.12+ (для нового запуска рекомендуется Node 22), npm и Python 3.8+ (рекомендуется 3.12). Python-проект использует стандартную библиотеку; `requirements.txt` намеренно не содержит сторонних зависимостей.

Откройте терминал в корне распакованного проекта:

```text
npm ci
python -m collector.runner collect
npm run dev
```

Откройте адрес, напечатанный Vite, обычно `http://127.0.0.1:5173/`. Во второй вкладке интерфейса «Наблюдение» появятся реальные проверенные товары. «Находки» могут быть пусты — это нормальный результат.

`collect` сохраняет состояние в `runtime/state.json`, экспорт в `public/data/catalog.json`. Файлы содержат реальное время и источник каждого наблюдения. Приложенный JSON — снимок **реальных запросов**, не demo; свежесть проверяется интерфейсом. В новом репозитории можно заменить его пустым набором с теми же полями, `generated_at=null`, `last_success=null`, `offers=[]`, `sources=[]`.

Непрерывный локальный цикл, независимый от открытого сайта:

```text
python -m collector.runner watch --interval 900
```

Минимум цикла — 300 секунд; по умолчанию 900. Компьютер должен работать. `Ctrl+C` останавливает цикл. Для запуска после перезагрузки добавьте эту команду в Планировщик заданий Windows (действие: `python.exe`, аргументы: `-m collector.runner watch --interval 900`, рабочая папка: корень проекта) или в systemd на Linux. Не запускайте одновременно два писателя одной истории.

Если процесс аварийно завершился, может остаться `runtime/collector.lock`. Сначала убедитесь, что старого процесса нет, затем удалите только этот файл. Состояние JSON остаётся атомарным.

Проверки и статическая сборка:

```text
python -m unittest discover -s tests -v
python scripts/check_public.py
npm test
npm run build
npm run preview
```

При специфичном Windows sandbox EPERM для esbuild разрешите среде чтение дерева проекта/родительских каталогов. В обычном терминале проекта дополнительных флагов не требуется.

В PowerShell при запрете `npm.ps1` используйте `npm.cmd` вместо `npm`. Vite не наблюдает за `public/data`, `runtime` и `.cache`, чтобы не удерживать заменяемый JSON-файл в Windows; интерфейс обновляет данные через fetch раз в минуту.

## 2. Создать репозиторий

Создайте пустой **публичный** репозиторий `price-hunter` в своём GitHub без начального README. В терминале проекта:

```text
git init
git add .
git commit -m "Initial Price Hunter"
git branch -M main
git remote add origin https://github.com/YOUR_NAME/price-hunter.git
git push -u origin main
```

Замените `YOUR_NAME`. Авторизация выполняется обычным Git Credential Manager/SSH; не помещайте токен в remote URL. `.env`, `runtime`, зависимости и кэш игнорируются. Проверьте список перед коммитом: `git status --short`.

Публичный сайт, ветка цен, SKU, история и условия доступны всем. Это не приватная админка. Репозиторий `price-data` в private не будет читаться анонимным frontend без отдельного безопасного канала публикации; токен в браузер не добавляйте.

## 3. Telegram-бот и chat ID

Создайте своего бота у официального [@BotFather](https://t.me/BotFather) командой `/newbot`. Сохраните выданный токен и отправьте своему боту `/start` в личном чате. [Инструкция Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).

После создания нового бота запустите **локально**:

```text
python scripts/setup_telegram.py
```

Помощник скрыто запрашивает токен, выполняет `getUpdates`, извлекает chat ID единственного личного чата и сохраняет оба значения в игнорируемый `.env`. Он не выводит token, chat ID, сообщения или ответ API в консоль. Если чатов несколько, webhook настроен или сообщений нет, помощник прекращает работу без вывода личных данных. Используйте отдельного нового бота для Price Hunter.

`.env.example` — пример формата. Сборщик читает Telegram-переменные из `.env` или окружения; переменные окружения имеют приоритет. Для получения ID не нужны сторонние боты. Не запускайте помощника в CI: для CI используйте Secrets.

Тест связи только по явной команде:

```text
python -m collector.runner test-telegram
```

## 4. Secrets и переменные GitHub

Откройте Settings → Secrets and variables → Actions → Secrets. Добавьте:

- `TELEGRAM_BOT_TOKEN` — токен бота.
- `TELEGRAM_CHAT_ID` — значение из локального `.env`.
- `CLOUDFLARE_API_TOKEN` — Cloudflare API token с разрешением Account → Cloudflare Pages → Edit для нужного аккаунта.
- `CLOUDFLARE_ACCOUNT_ID` — ID аккаунта Cloudflare.

Во вкладке Variables добавьте:

- `CLOUDFLARE_PROJECT` — имя созданного Pages-проекта, например `price-hunter-yourname`.
- `PRICE_HUNTER_ENABLED=true` — **после успешного ручного сбора**, если хотите включить расписание Actions.
- `PRICE_HUNTER_RUNNER_LABELS` — необязательно: `["self-hosted", "price-hunter"]` для собственного исполнителя; без переменной используется облачный `ubuntu-latest`.

В Settings → Actions → General → Workflow permissions разрешите запись содержимого для своего сборщика. `Collect prices` использует `contents: write`; тесты и публикация — read. Не копируйте секреты в `config/monitor.json`, `VITE_*`, JSON или исходники.

Workflow `Test Telegram` запускается отдельно через Actions → Run workflow и подтверждает доставку теста. Отсутствие Secrets не мешает сбору: уведомления отключаются с понятным сообщением.

## 5. Сайт и расписание

В Cloudflare Dashboard создайте Pages-проект **Direct Upload**, задайте production branch `main`, добавьте указанные Secrets и Variable, затем Actions → **Publish interface** → Run workflow. В README не обещается уже опубликованный сайт: аккаунты в этой среде не подключены.

Cloudflare вернёт адрес `https://PROJECT.pages.dev`. Workflow устанавливает публичные `VITE_REPOSITORY=owner/repo` и `VITE_DATA_URL=https://raw.githubusercontent.com/owner/repo/price-data/catalog.json`. После изменения исходников деплой повторяется; после сбора цен — нет. До создания ветки `price-data` интерфейс покажет ошибку HTTP 404 и предложит первый сбор.

Для облачного запуска не нужен собственный runner: Actions → **Collect prices** → Run workflow. После проверки результата включите `PRICE_HUNTER_ENABLED=true`. Сбор запускается на минуты `7,22,37,52` каждого часа и вручную через `workflow_dispatch`, затем завершается. Actions не является постоянным сервером. Для собственного исполнителя добавьте `PRICE_HUNTER_RUNNER_LABELS=["self-hosted", "price-hunter"]`, откройте Settings → Actions → Runners → New self-hosted runner, следуйте официальным командам GitHub и добавьте метку **`price-hunter`**. Собственный runner должен быть включён; не запускайте на нём чужие непроверенные ветки.

GitHub может задерживать или пропускать scheduled jobs; расписание работает из default branch, а после 60 дней отсутствия активности публичного репозитория может отключиться. Перепроверьте вкладку Actions и включите workflow вручную при необходимости. [Schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

**Локальная альтернатива Actions:** для публикации данных в `price-data` выполните один раз в обычном Git-клоне:

```text
python -m collector.gitdata prepare --path runtime/data
python -m collector.runner watch --state-dir runtime/data --persist-git --interval 900
```

Нужен доступ Git к вашему репозиторию. Это создаёт/читает отдельный worktree ветки данных и публикует JSON. Секреты Telegram остаются в локальном `.env`. Не включайте в то же время Actions-сборщик этой же ветки: допустим только один писатель. Локальный режим с обычным `runtime` не публикует состояние автоматически.

## 6. Первый сбор и диагностика

Actions → **Collect prices** → Run workflow. Оставьте `probe=false` для обычного сбора. Он создаёт ветку `price-data`, сохраняет состояние и при настроенном Telegram отправляет только подходящие находки. По умолчанию используется облачный runner; для собственного исполнителя он должен быть подключён.

`probe=true` дополнительно проверяет доступность всех магазинов **без Telegram-уведомлений**. Локально:

```text
python -m collector.runner probe
```

Проверка реального доступа **в GitHub Actions здесь не выполнена**. Когда ваш runner выполнит запросы, поле `actions_verified` выставляется только у источника с успешно разобранными товарами. Успешный hosted build интерфейса не доказывает доступность магазинов.

Результат в Actions Summary показывает число карточек и статусы источников. «Доступен» означает успешно разобранные карточки за запуск, «частичный» — часть проверок завершилась ошибкой, «не реализован» — страница может открываться, но готового парсера нет. Блокировки, авторизация, robots и таймауты не маскируются.

## 7. Настройка поиска и проверка доказательств

Редактируйте **`config/monitor.json`** и коммитьте изменения. В интерфейсе доступен экспорт JSON и ссылка на GitHub; кнопок фиктивного сохранения серверных настроек нет. Экспорт отражает конфигурацию на момент сборки сайта. Фильтры главной страницы меняют только просмотр.

`enabled_categories` по умолчанию включает все запрошенные полезные группы. **Реальный discovery сейчас настроен только на четыре проверенных категории Technodom**; включение продуктов/одежды само по себе не добавляет неизвестный источник. Добавляйте категорию в `shops.technodom.categories` только после проверки реального URL, с `key`, `label`, `url`. Дополнительная ссылка:

```json
{"url":"https://www.technodom.kz/astana/p/naushniki-apple-earpods-usb-c-288036","category":"gadgets"}
```

Поместите её в `shops.technodom.watch_urls`. Это дополняет автоматический поиск, не заменяет его. При большом числе ссылок они обходятся по очереди. `max_products` ограничивает карточки за запуск, `max_tracked` — активные записи, `network.interval` — задержку, `max_requests` — запросы одного источника. Максимум запросов/товаров ограничен валидатором.

`threshold` допускает 90–100, `preliminary_alerts` по умолчанию false. Для предварительных уведомлений включите true: требуется независимая/историческая база, а не зачёркнутая цена; сообщение помечается «НЕ ПОЛНОСТЬЮ ПРОВЕРЕНО».

Для ручного подтверждения отсутствующих публичных условий существует `verified_facts`: ключ — точный товарный URL; обязательны `checked_at` в ISO UTC, публичный `evidence_url`, `values`. В `values` допустимы brand, model, quantity, volume, bundle, variant, condition, delivery_cost, mandatory_cost, astana, full_payment, conditions, expiry. Цена не может переопределяться. «Нет отдельного объёма/варианта» укажите явно текстом, только после проверки. Факты действуют **24 часа**, затем снова неизвестны. Для `identity_verified` нужны все семь полей идентичности. Не вписывайте доставку 0 или новое состояние без доказательства.

Точная рыночная группа включает бренд, модель, вариант, комплект, объём, количество и состояние; названия и внутренние SKU не используются как доказательство равенства. У продавца берётся только одно независимое предложение, исключаются недоступные/устаревшие цены и явные выбросы. Желательно минимум три других продавца; меньше — предварительная уверенность. Сам товар в рыночную медиану не входит.

Историческая база — медиана дневных медиан цены самого товара за предыдущие 30 дней, исключая последние 24 часа. Нужно минимум 7 наблюдений за минимум 3 разных дня и достаточно устойчивый уровень (MAD/median ≤20%). При неизменной цене сохраняется одно наблюдение в сутки; при изменении — новая точка. Один день частых запусков не заменяет историю. При изменении известной упаковки, варианта или состояния временной ряд сбрасывается.

Итог = цена + подтверждённое получение + обязательные расходы. Неизвестное не превращается в 0. Если итог неизвестен, может показываться только верхняя оценка скидки, с явной пометкой. Исторический базис цены товара консервативно сравнивается с текущим итогом; прежняя доставка не приписывается прошлой цене. Кешбэк и рассрочка не уменьшают итог. Цена, доступность, точный товар и получение в Астане должны подтверждаться для статуса «подтверждено».

Исключаются запрещённые категории, явно неисправное и просроченное. Для еды без даты показывается «срок годности не указан». Автоматический текстовый отсев — дополнительная защита; подключая новые категории, вручную проверяйте их назначение. Уценка с непроверенным состоянием не сравнивается с новым товаром как подтверждённая выгода.

## 8. История, уведомления и сбои

`price-data/state.json` содержит ограниченную товарную историю, курсоры и журнал уведомлений с идентификаторами **товаров**, без chat ID, токенов, cookies или пользовательских сообщений. `catalog.json` — очищенная выдача для сайта, без журнала уведомлений. Git cache и временный диск runner не являются источником истины.

Уведомление повторяется только при снижении сопоставимой цены ещё минимум на 10% от последней отправленной либо после явно наблюдавшегося отсутствия и возврата наличия. Это проверяется между запусками через сохранённый журнал.

Перед внешней отправкой резервируется `pending` и **публикуется в ветку данных**. Затем вызывается Telegram; `sent=true` сохраняется только после подтверждения `ok=true` и message ID, сам Telegram message ID не публикуется. При подтверждённом отклонении API резерв откатывается для повторной попытки. Для 429 учитывается retry_after, максимум три попытки; неопределённая сетевая ошибка не повторяется вслепую.

**Сбой между отправкой и сохранением:** Telegram не предоставляет идемпотентный ключ sendMessage. После перезапуска неизвестное `pending` подавляет повтор. Это снижает дубли, но может пропустить уведомление, если процесс умер до отправки. Обещания exactly-once нет. Сверьте бот и журнал, затем явно отметьте доставку:

```text
python -m collector.runner notify --state-dir runtime/data --output runtime/data/catalog.json --persist-git --resolve-pending PRODUCT_ID
```

Эта команда ставит `sent=true`; без неё pending остаётся на проверке. Если выяснили, что сообщения точно нет, удалите **только соответствующий элемент** `notifications` в state.json и сохраните ветку перед следующим запуском. Не удаляйте весь журнал. Исправление предварительной находки отправляется, когда свежая проверка больше не подтверждает выгоду/наличие. При сбое Telegram исправление может прийти повторно после неоднозначной доставки — sendMessage не даёт гарантии exactly-once.

При трёх последовательных сбоях реализованного источника отправляется одно служебное сообщение до восстановления. Недоделанные адаптеры не засыпают Telegram ошибками. Сервисы могут менять доступ по User-Agent/среде; результат `probe` важнее прошлой таблицы проверки.

Сохранение ограничено 30 днями и 240 точками на товар, по умолчанию 500 активными товарами. JSON переписывается атомарно только при изменении содержимого. Метки проверки/состояния считаются изменениями для контроля свежести. Git-коммит создаётся только при diff; старые Git-коммиты автоматически не удаляются — следите за объёмом репозитория, при необходимости обслуживайте историю ветки отдельно, с сохранением актуального журнала. Force-push сборщиком не выполняется.

При несовместимой версии состояния или конфликте push процесс завершится ошибкой, а не перезапишет чужую историю. При ошибке одного магазина остальные проверки продолжаются. URL проверяются по точным доменам HTTPS, DNS должен вести на публичные адреса; соединение привязано к проверенному IP с TLS-проверкой имени. Перенаправления тоже проходят проверку. robots.txt недоступен/запрещает путь — сбор прекращается. CAPTCHA, авторизация, блокировки не обходятся.

Признаки сбоя: устаревшее время в интерфейсе, красный workflow, blocked/error в «Источниках», ноль успешных карточек при доступных категориях. Пустая лента находок при успешных наблюдениях не является сбоем.

## 9. Статус источников и проверки

Подробные реальные URL и HTTP-результаты: [research/sources.md](research/sources.md). Первоначальная проверка обычным urllib получила блокировки у большинства магазинов; последующая проверка самим сборщиком с его обычным User-Agent смогла открыть страницы Sulpak, Alser, Kaspi, однако парсеры этих магазинов всё ещё не реализованы. Изменение доступности не означает обход защиты.

Реальные локальные запуски Technodom проверили 16 товаров за запуск, получили ссылки на 92 товара четырёх первых страниц. Повторные запуски восстановили историю и обнаружили новые карточки. Подтверждённых аномалий не обнаружено. Fixtures в `tests/fixtures` — очищенные реальные ответы для тестов; они никогда не загружаются обычным сборщиком в выдачу. Demo-товаров нет.

Проверены Python-тесты расчётов, цены/валюта, упаковки/варианты, зачёркнутая цена, история, независимость продавцов, неизвестные расходы, устаревшие источники, robots/SSRF, атомарное состояние, дедупликация и ошибки Telegram. Интеграционный тест создаёт bare remote и независимые worktree: история и pending/sent восстанавливаются, stale push отклоняется. Frontend-тесты проверяют JSON, неизвестные суммы, опасные ссылки и свежесть; TypeScript и production-сборка проходят. Визуальная проверка выполнена локальным Edge; конечный хостинг и Telegram с реальным ботом требуют ваших подключений.
